# 教师端学生筛选与批量管理：实现前失败清单

用户要求：教师端拥有学生筛选和批量管理，移除创建时间筛选。后续已新增最后提交时间，并移除学号情况筛选；学号展示及关键词搜索保留。管理员和教师界面均去掉创建日期筛选；保留日期展示。教师可按关键词（用户名、姓名、邮箱、学号）、自己的班级、AI 额度筛选，跨页勾选后批量调整班级、移出班级、重置密码、AI 额度和删除学生账号。

实现前枚举失败方式：
- 教师访问或修改其他教师的学生，混入一个越权 ID 导致前面的学生部分写入；目标班级不属于自己。
- 移出后仍保留教师管理权限，或允许操作无班级学生；管理员正常批量操作被教师范围校验误伤。
- 并发调班后基于旧成员关系授权；单班级约束或课程权限不一致。
- 跨页勾选丢失或影响未选择学生；筛选或重置后旧选择仍保留；删除/移出后列表不刷新。
- 搜索仅匹配姓名而遗漏学号、邮箱；同名班级误匹配；额度尚未加载就误判为有额度。
- 密码不合法、空列表、超过 500 人、不存在学生或班级未拒绝；批量失败没有保留选择供重试。
- 请求乱序覆盖最新结果，刷新失败继续显示旧数据；获取 AI 额度产生每人一个请求或失败被伪装为正常额度。
- 教师端原有详情、编辑、导入等流程失效；单个“删除”实际移出而文案与批量删除账号混淆。
- 创建日期选择器残留在管理员或教师页面；依赖日期筛选的旧 E2E 失效。

验证采用真实 Spring Boot/MySQL/Redis 和 Playwright 浏览器 E2E，不新增单元测试。报告、截图和清理结果保存至 output/teacher-student-management-e2e，可复跑 node tools/e2e/teacher-student-management.mjs。管理员原有 E2E 同步去掉创建日期用例并保留其余回归覆盖。
