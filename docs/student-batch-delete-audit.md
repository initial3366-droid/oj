# 学生批量删除排查

实现前失败场景与验证范围：

- 缺失或错误操作密码、非管理员访问后台批量接口，必须拒绝且不修改学生。
- 批量删除普通学生及有提交、用例结果、做题状态的学生，应完整清理个人记录。
- 不存在的学生混在批次中，必须整批拒绝，保留已有学生。
- 学生仍拥有共享题目、比赛或题单时，必须先转移归属；禁止删号后留下孤儿内容。
- 后一个学生不能删除时，前一个学生和积分、成员关系必须随事务回滚。
- ADMIN/TEACHER 与 USER 的数字 ID 相同，不得误判为学生拥有的内容。
- 调班、移出班级、重置密码、重置 AI 额度只影响所选学生，非法参数不能部分执行。

验证使用本地真实 Spring HTTP、MySQL、Redis；只创建和清理专属临时夹具。
后台操作密码的成功路径需要 `QOJ_E2E_ADMIN_OPERATION_PASSWORD`，不记录密码或令牌。
未提供操作密码时，通过教师接口验证共用批量服务的成功路径，并明确区分后台密码拒绝验证。
线上访问地址和异常日志尚未提供，本地验证不能证明线上故障原因。

  后台接口覆盖五种操作的缺失/错误密码拒绝。未验证真实后台操作密码成功路径。
