# 提交展示批量读取：实现前失败场景

本批范围：普通/管理提交列表、管理 CSV 导出、详情统计。先写真实 HTTP E2E 并取得旧实现基线，再修改生产代码；不新增单元测试。

- 空页不能产生空 IN 查询，也不能多查全表；页数、上限和排序不变。
- 多提交复用同一用户/题目时关联查询不能随行数增长；大导出不加载测试点正文来聚合。
- 公共比赛标题动态读取 contest_problems.problem_id 所指原题；管理标题优先比赛快照标题再原题再数字 ID。两者不可混同。
- 缺失关联、空白标题、code_length 缺失与代码长度回退保持原行为。
- 测试点计数：0 条、AC/WA/ACCEPTED/小写 ac；SQL 原有 collation 计数语义必须保留。
- 时间/内存为 null、0、负数、正数；只使用正数最大值回退，管理端保留原始汇总值。
- 明细按 case_no 排序，输出正文和错误信息保持一致；列表仍不返回代码与明细。
- 教师只能看到自己的班级，管理明细不能越权，学生不能访问管理接口。
- 冻结榜单过滤、本人查询例外、比赛期间他人 PENDING 遮罩、管理员绕过保持不变。
- 读请求不得修改业务行或 Redis 状态；通过前后 HTTP 快照与业务表摘要核对。
- 统计来自实际 JDBC/MyBatis Preparing 日志，剔除后台线程。记录 SQL 指纹、表名、次数，不用 Mapper mock 替代。
- 测试只写随机临时数据库、独立 Redis；成功或失败都关闭进程并清理测试资源。

详情的 AC 数继续使用数据库条件聚合，而非 Java String.equals，以保留数据库 collation 对大小写的既有语义。并发判题中不同 SQL 的快照一致性变化需要另列限制，不伪称完成并发压力验证。
