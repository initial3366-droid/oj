# 比赛答疑与广播实施前验收清单

- 匿名、未报名、待审核、被拒绝、被取消报名者通过页面或直接 API 读取广播/答疑。
- 学生伪造 participantId 或消息类型，读取他人问题、代发问题、发送广播。
- 教师访问非自己比赛；管理员/教师/学生 ID 重合导致串权。
- 广播只在介绍页可见，做题页看不到；跨页面丢失未读；刷新或断线漏掉广播。
- 广播弹窗抢焦点、遮罩阻止输入、重置编辑器、播放声音，干扰选手。
- 后台无法选择提问学生、回复发错学生、广播未向所有已报名者开放。
- 消息不持久化、分页丢数据、轮询重叠导致乱序或重复、请求返回前切换比赛泄漏旧数据。
- 网络失败丢失输入、重复提交产生重复消息；空消息、过长消息、HTML/XSS。
- 取消报名后仍显示已缓存消息；后台页或普通练习页出现选手入口。
- 标为已读超过可见范围；多标签页已读游标回退。

验证采用真实 MVC/MySQL/Redis 与多个隔离浏览器，保留可重复运行脚本、report.json 与截图。

## 实施与验证结果

- `node tools/e2e/contest-messaging.mjs`：11 项真实后端/数据库/多浏览器端到端检查通过。
- `npm run build` 与后端 `mvn test -q` 通过。
- 报告与截图：`output/contest-messaging-e2e/`；临时账号、比赛及消息已清理。
- 部署需同时更新前后端，并由 Flyway 应用 `V106__contest_messaging.sql`。
- 消息以数据库记录为准，页面每 3 秒增量同步，恢复前台或网络后补收；未读游标按比赛和选手存储。
- 选手端入口覆盖 `/contests/:id` 与带 contestId 的做题页。提示无声音、无遮罩、不移动焦点，10 秒后收起，未读徽标继续保留。
