# QOJ Agent：512K 上下文和浏览器历史

## 方案依据

OpenAI 的 [Compaction](https://developers.openai.com/api/docs/guides/compaction) 在阈值处压缩旧上下文，保留继续任务所需状态；支持无状态输入数组续接。Claude 的 [Context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows) 同样将摘要压缩作为长任务主要方案，并明确工具和输出都占用窗口，缓存并不会扩大窗口。

QOJ 当前使用后台配置的 OpenAI-compatible Chat Completions，不要求供应商专有压缩接口。采用客户端管理完整历史、普通模型生成摘要、服务端临时执行工具的方式。

## 当前行为

- 产品上下文上限512,000 tokens，AI设置新增“模型上下文窗口”，真实容量更小的模型需按服务商能力填写，范围8,192–512,000。原有模型、URL和密钥保持不变。
- 为输出保留 `min(65,536, 模型窗口/4)`，为系统提示和工具定义预留额外空间。前端超过可用输入预算80%时，保留近期完整轮次，分批将旧消息压缩为摘要。
- 摘要保留目标、约束、关键ID/路径、完成与待办、真实操作结果，明确不能当成新的用户授权。摘要失败时停止本次发送，保留完整记录，不静默截断。
- 附件保留引用，通过现有文件工具按需读取。上传附件仍走现有服务器文件服务，并不等于聊天历史本地化；本次没有改动附件服务。
- 工具执行时按实际工具schema、工具调用/结果、系统提示、媒体估算预算。超阈值压缩较旧的完整工具轮次，不拆分调用和结果；超大单条结果明确报错。
- 页底显示准备发送的文本/图片/引用估算、百分比、回复预留及压缩条数；另显示最近一次模型输入token，有服务商usage时标注“服务商返回”，否则“估算”。估算使用ASCII约3字符/token，非ASCII约2token/码点，图片约4096token/张。不同模型分词和图片尺寸会影响误差，计数并非精确容量保证；缓存token仍属于上下文。

## 保存边界

完整消息和摘要存于当前站点浏览器的IndexedDB，按JWT账号标识分区，流式回复定时保存，完成/失败时立即保存。支持本地导出；清除浏览器数据、换浏览器或换设备不会自动同步记录。存储失败会显示错误。

聊天流、停止接口和标题管理不再写MySQL聊天表；旧保存/改名/标题生成接口返回410，阻止旧客户端继续落库。原数据库记录不自动删除；“迁移旧记录”逐条读取、确认本地写入成功后删除服务器记录，同时保留本地历史引用的附件。迁移中断的记录仍可重试。

任务执行状态只保存在进程内存中，完成即释放，未完成/待确认最长6小时后清理。Redis仅保存任务租约、停止标记及确认去重标记，不保存聊天正文、工具转录或摘要。后端重启后不能续接原任务，返回任务已过期；浏览器完整聊天仍在。多实例部署需会话粘性，续接命中其他实例会按过期处理，不重放写操作。

请求仍需将所选上下文临时发送到OJ后端和已配置模型供应商进行推理。兼容请求设置`store=false`，供应商自己的保留政策取决于其实现，不能由OJ承诺。业务操作的结果、审计日志、导入方案仍遵循原业务持久化规则。

## 可重复验证

- `npm run build`
- `npm run verify:template`
- `cd backend && mvn test`（既有189项测试，不新增单元测试）
- `node tools/verify-agent-local-context.mjs`：默认连接5178，可用`QOJ_FRONTEND_URL`覆盖。浏览器真实渲染、API固定响应，不调用真实收费模型。验证多轮上下文、刷新恢复、账号隔离、超过40条/60000字符、分批摘要与失败保留。产物位于`.runtime/agent-local-context/`，包括报告、截图、Playwright trace。
