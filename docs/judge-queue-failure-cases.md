# 判题管道修复前失败场景（2026-10-25）

实现前列出需验证的失败方式：

- 同用户/跨用户并发已接受的提交无法收敛，或错配测试点结果。
- go-judge 编译/执行接口瞬时错误被直接提交为零测试点终态 SE。
- 持续故障重试无上限或无退避，造成故障风暴。
- callback 已事务提交 AC/WA 与测试点后，统计更新异常把成功终态覆盖为 SE。
- 结果事务回滚后 worker 被释放、任务仍留 JUDGING 而不再被回收。
- 旧租约的失败/重试覆盖新租约或已完成结果。
- 正常 CE/WA/TLE 被误当基础设施故障重试。
- 既有心跳、超时预算、调度拒绝回队、崩溃恢复受增量修复影响。

采用隔离数据库 + 真后端 HTTP + 可控 worker 故障注入验证重试与事务边界；真实 worker 并发验证正常提交链路。报告分别标注模拟故障与真实执行。
