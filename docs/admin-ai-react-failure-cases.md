# ReAct 文件导入：失败场景与验收

## 明确生成测试点：实现前失败清单

- 用户上传题面并明确要求生成新测试点，却被原文导入规则禁止。
- 多轮聊天已经授权生成，后续“继续”丢失授权；随后禁止生成却继续执行。
- 附件、助手回复或工具输出中的生成要求被误当成用户授权。
- 只要求原文导入时，模型绕过校验猜测新输入或答案。
- 标程编译失败、超时、样例不匹配或输出过大，却保存为有效测试点。
- 只要求生成预览时擅自入库；给已有题追加测试点时覆盖已有数据或样例。
- 大批测试点反复编译、生成中停止仍继续执行，或续跑丢失已算出的数据。

验收使用真实浏览器、Spring AI、MySQL/Redis 和 go-judge；保存事件、数据库数据及截图。不添加单元测试。

当前聊天支持 `run_code` 沙箱计算和 `generate_test_cases` 生成批次。明确的生成目标只从实际用户聊天取得，多轮继续沿用，后续禁止生成会撤销；附件和助手文字不会授予生成权限。AI 提供输入或生成器及标程，沙箱计算原始答案并核对给定样例。通过样例不等于算法正确性证明；构造题和 SPJ 仍需专门校验。

每批最多 200 个测试点，使用现有 C/C++/Java/Python 语言白名单、每点 2 秒 / 256 MB 限制、顺序执行和沙箱并发配额；批量标程只编译一次。生成器输出 JSON 字符串数组，完整批次保存在当前管理员独享的 Redis 引用中 6 小时，模型只接收摘要。新草稿通过生成批次直接保存，已有题只能追加并去重，不覆盖样例。只要求预览时不入库；原文导入继续检查已有答案的真实来源。

本地启动已有判题沙箱并复验：

```sh
docker compose --env-file .env -f docker/go-judge/docker-compose.yml up -d --build
QOJ_E2E_SCRIPTED_AGENT=1 QOJ_E2E_REACT_ONLY=1 QOJ_E2E_OUTPUT_DIR=output/admin-ai-generation-e2e node tools/e2e/admin-ai-stream.mjs
QOJ_E2E_LIVE_REACT=1 QOJ_E2E_GENERATION_ONLY=1 QOJ_E2E_OUTPUT_DIR=output/admin-ai-generation-live-e2e node tools/e2e/admin-ai-stream.mjs
```

产物包含 `report.json`、生成事件、数据库核对数据及浏览器截图。上线需更新后端并保持现有 go-judge 可用，无新增数据库迁移或配置项。

实现前的风险清单与端到端验收目标：

- 模型只回答、不读取真实文件：真实模型流程必须留下 `list_files`、`read_file` 的 Action 与 Observation，最终内容能对应文件。
- 模型首次配对错误：工具返回校验错误，继续交给模型修正；不能把失败伪装成成功。
- 非标准文件名、不同目录、同名测试点：按文件内容及用户说明分组，用原文件引用配对，入库原文保留。
- 恶意文件要求调用管理操作：文件仅作为不可信材料；不能授予权限或确认导入。
- 模型未经用户要求而入库：权限由管理员账号角色授予，任务目标按多轮真实用户消息延续；明确只分析/暂不保存时阻止写入，后续确认可继续。附件和模型回复不授予权限、不改变用户目标。
- 模型修改已审核内容：提交工具只接收计划 ID，服务器使用用户提交的审核快照，拒绝其他计划。
- 引用当前对话之外的文件、其他账号的计划：工具作用域与账号校验必须拒绝；不能读取或导入。
- 重复点击、断线后重试：导入计划幂等提交，不新增重复题目。
- 多题提交中部分无效：整个题库写入事务回滚。
- 无答案或模型编造答案：已指定的普通测试点必须提供有效原始答案；没有任何测试点时管理员可以保存私有未发布题面。数据来自附件文件、文档原文片段或用户实际聊天内容，模型编造的答案不能入库。
- 无限调用、巨大工具参数与输出：分段限制调用数和时长，批量读取有节选预算；重复调用复用结果，无进展时停止并说明。
- 用户停止、页面断线：在执行下一工具前检查连接；已完成操作保留结果，未确认写入不能发生。
- 历史刷新、错误或停止：执行摘要与导入计划入口需要持久化恢复。
- 现有图片、纯文本对话、标题和表格：回归现有端到端脚本，不能破坏原有行为。

复验使用现有 `tools/e2e/admin-ai-stream.mjs` 的真实 Agent 模式，记录工具调用结果、浏览器截图与数据库验证；不新增单元测试。

## 通用聊天与续跑：实现前的失败清单

- 不上传附件的聊天未启用工具，无法查询真实题库与后台概况。
- 用户必须先点解析按钮，操作目标与聊天消息分离。
- 25 次有效操作就报错；同一工具重复参数也会消耗调用预算并重复写入。
- 单轮耗时较长、文件较多时进度丢失，续跑重复读取或重复导入。
- 同一批工具在分段时只执行一部分，丢失剩余操作或没有完整 Observation。
- 自动续跑新增用户消息或新助手回复，历史顺序和耗时失真。
- 停止生成仍发起下一段；断线后进度丢失；另一账号窃用继续标识。
- 文件内容中的“同意导入”被当作用户授权；仅分析请求却执行写入。
- 直接聊天要求导入时仍强迫打开解析界面；确认上一个方案时不能找到已保存的计划。
- 通用工具查询返回密钥或密码；写入绕过既有业务校验、产生公开题目。

端到端验证须覆盖：超过 24 次有效操作及自动续跑、重复操作只执行一次、无附件的真实数据查询、批量文件读取、直接聊天导入、停止与权限隔离；同时输出 SSE Action / Observation / continuation 和数据库校验产物。

## 当前执行方式

超级管理员的普通聊天也进入原生工具循环，可查询概况、题库、测试点、文件夹、比赛和提交；通过当前聊天创建并保存未发布题目。上传附件后直接发送分析或导入要求，不再显示独立的解析按钮。只整理的方案仍可从消息链接核对。

每段最多执行 256 次新操作、200 轮模型调用、持续约 15 分钟，完整工具对话、待处理调用和成功结果缓存保存至 Redis 6 小时。前端最多连续续跑 32 段或约 1 小时，之后保留“继续处理”入口；停止或刷新也可恢复同一助手消息。续跑标识绑定管理员、聊天和消息，Redis 锁按聊天与助手消息绑定，避免同一消息同时执行。停止按钮发送显式取消信号，模型等待时每 250 ms 检查；停止接口等待 SSE 保存中断状态后再返回，避免 Nginx 断线后旧任务占锁。同参数失败结果不会缓存，允许模型先纠正缺失步骤再重试。

复验：

```sh
npm run build
QOJ_E2E_SCRIPTED_AGENT=1 QOJ_E2E_REACT_ONLY=1 node tools/e2e/admin-ai-stream.mjs
QOJ_E2E_LIVE_CHAT=1 node tools/e2e/admin-ai-stream.mjs
QOJ_E2E_LIVE_REACT=1 QOJ_E2E_REACT_ONLY=1 node tools/e2e/admin-ai-stream.mjs
```

模拟提供商启动独立的 18081 后端，由真实 Spring AI SDK 调用本地 HTTP 提供商，操作使用实际业务服务及 MySQL/Redis。测试不修改已有模型设置。产物位于 `output/admin-ai-stream-e2e/`，包括报告、Action/Observation/continuation 记录、数据库校验和截图。

## 停止后继续聊天：修复前失败清单

- 点击停止时浏览器还没收到任务 token，只取消前端连接，后端模型或工具继续运行。
- 自动分段交接时停止标志被下一段清除，刷新后出现 complete。
- 后端取消接口失败被前端吞掉，界面误显示停止成功。
- 旧 SSE 回调在停止后写入 complete / pending，覆盖已持久化 stopped。
- 教师账号走普通聊天流而不是 ReAct，必须使用相同后端取消信号，中断无增量的模型请求。
- 停止后本地 version 落后服务器，再发送新消息无法保存或输入框未解除锁定。
- 刷新将停止回复误当作普通完成，继续处理与发送新请求混淆。

端到端场景：阻断最初 run 事件但保留代理上游，点击停止并验证真实模型连接中止、工具计数不增加、刷新仍为 stopped；停止后同一聊天发送新请求并保存 4 条消息；取消接口临时失败明确提示且可重试；停止与最后一段交接不产生 complete 覆盖。输出数据库状态、模型连接与工具事件的可复验 JSON。

- `npm run build`：类型检查与发布构建通过。
- `mvn test`：204 项既有后端测试通过；未新增单元测试。
- `QOJ_E2E_SCRIPTED_AGENT=1 QOJ_E2E_REACT_ONLY=1 QOJ_E2E_NGINX=1 QOJ_E2E_OUTPUT_DIR=output/admin-ai-stop-nginx-e2e node tools/e2e/admin-ai-stream.mjs`：9 项真实 SDK / REST / MySQL / Redis / Nginx 场景通过。
- `QOJ_E2E_OUTPUT_DIR=output/admin-ai-stop-regression-e2e node tools/e2e/admin-ai-stream.mjs`：19 项上传、解析、表格和流式结束场景通过。
- `node tools/e2e/admin-ai-history.mjs`：16 项聊天持久化场景通过。

取消使用已有聊天与助手消息 ID，不再依赖浏览器是否收到任务 token。服务端按消息写入 Redis 取消标志，取消模型 HTTP Call，退出后保存 stopped 并释放执行锁。只有明确的“继续处理”请求清除旧取消标志；自动分段不清除它。浏览器停止失败时提示并提供重试，成功后获取服务器版本再允许发送。停止时已接收到的增量内容一并保存，旧快照不能把 stopped 改回 complete 或 pending。已完成的工具写入不会因停止而撤销。

本次无数据库迁移或新增环境变量。部署需同时更新前后端；仅刷新旧发布版本不能获得修复。

## 管理员写入与文档测试数据：修复前失败清单

- 管理员已要求保存题目，但后续说“只用原文答案，按刚才要求继续”，因最后一句没有写入关键词而返回权限错误。
- “不要生成新答案”被混同为禁止创建题目，未区分用户任务约束与账号权限。
- 前一轮只分析，用户下一轮确认，无法直接提交真实导入方案。
- PDF / DOCX 等文档中的原有输入输出只能被错误地作为整份文件引用，不能按原文片段导入。
- AI 编造的答案片段必须拒绝，不能借文档片段支持生成新答案；不同账号不能引用别人的文件/计划。
- 只有题面的材料无法保存为未发布题目，迫使 AI 尝试无效测试点；学生/教师不能借新入口越权保存。
- 审核面板不能查看文档片段配对，旧独立 .in/.out 映射必须继续工作。
- 机器人把内部工具名、原始报错表格当成最终答复，未给出清楚的题目保存结果或缺失资料。

验证：真实 SDK 经 Nginx 调用后端，模拟多轮继续、确认导入、PDF 两组原始样例导入、伪造答案片段拒绝、无测试点未发布保存和仅分析不入库。数据库验证题目/测试点/发布状态，保存原始材料、事件、对话与截图。

## 自动导入与空样例：修复前失败清单

- 自动保存成功后，正文仍保留“查看并确认导入方案”，旧聊天刷新后也无法区分未提交方案与已导入结果。
- 空样例输入、空样例输出或二者都为空被 DTO、草稿提交和样例替换校验拒绝或丢弃；空格、换行被前端 trim 改写。
- 真实存在的零字节 .in/.out 文件、明确引用的空原文片段、成功标程的空输出被混同为缺少测试数据。
- SPJ 可以没有 .out 文件；普通判题缺少答案文件仍应拒绝，不能用允许空文件掩盖不存在的答案。
- 重开已导入方案不应再次调用 Agent、再次确认或新增题目；仅分析方案仍应能查看和后续确认。
- 空样例字段缺失/null 与已明确提供空字符串必须区分，非空原文引用仍须校验真实性。

验证：真实 SDK 经 HTTP 调用聊天工具并导入 ZIP，数据库检查零字节与空白字符精确保留；浏览器检查自动导入和历史方案按钮；真实隔离沙箱计算空输出。保持跨账号校验、缺答案拒绝及幂等提交。

修复：自动导入直接展示已保存的未发布题目，不再向回答插入待确认链接。历史聊天中旧链接会查询真实方案状态，已导入时显示“查看导入结果”，打开后只展示结果；用户要求先分析的方案仍可查看和确认。空字符串及空白字符在样例、普通测试点、SPJ、文件/ZIP 和后台编辑中原样保存；null 或缺少答案文件仍按对应规则拒绝，SPJ 允许没有答案文件。空文件与空原文片段由实际上传和来源引用校验，没有伪造占位数据。

验证结果：修复前 6 项自动导入、空文件、空输出、空片段和历史按钮场景均复现失败；修复后连同后台编辑共 7 项全通过，完整聊天/附件/权限/停止/流式回归 56 项通过，后端现有测试 204 项通过。可复验报告及截图在 `output/admin-ai-empty-e2e/` 与 `output/admin-ai-empty-regression-e2e/`。无数据库迁移，线上更新前后端构建产物后生效。

## 执行提示重复：修复前失败清单

- 每次工具 action 都向正文追加提示，同一种查询分页 40 次会留下 40 条“查询后台数据…”，刷新后仍存在。
- 缓存命中的调用同样发出执行提示，让用户误以为后台反复执行相同操作。
- 查询概况、题库、比赛、测试点共用模糊提示，无法判断当前处理对象及页码。
- 读取文件、生成数据等操作的提示不能在同一位置更新；工具结束后看不出已进入整理结果阶段。
- 完成、暂停、失败、切换聊天和再次发送后，旧执行状态可能误留在新消息上。
- 多段续跑需要保留所有真实调用及导入结果，去除提示不能截断任务或破坏缓存写入去重。

验证使用发布构建、浏览器及 HTTP SSE，覆盖连续事件、缓存复用、状态替换、完成/暂停/失败和刷新；真实 SDK 经过后端执行 40 页查询与重复创建草稿，检查事件、数据库结果和持久化正文。保存可重复运行的脚本、事件记录与截图。

修复：工具状态只由 SSE `tool` 事件驱动前端当前助手消息的一条临时状态，不再作为 `delta` 拼接或保存。查询提示区分对象和页码；缓存命中在 action 和 observation 中一致标记 `cached`，不重新展示执行。最终回复、导入方案链接与实际保存结果仍正常持久化。状态在完成、暂停、错误时清除，新任务重新初始化。模型提示要求复用已有观察，避免重复进度播报。

验证结果：修复前 4 项重点 E2E 均复现失败，修复后全部通过；聊天/上传/输入法/表格/停止回归 25 项通过，既有后端测试 204 项通过。重点事件、截图和正文记录在 `output/admin-ai-progress-e2e/`，回归记录在 `output/admin-ai-stream-e2e/`。无新增数据库迁移，线上需更新前后端构建产物。
