# 后台聊天错误码恢复排查

修改前检查：

- HTTP/SSE 错误只保留 message，丢失 400/403/404/409/429/500/502/503/504，无法正确区分恢复行为。
- 请求开始前的 409（任务仍在运行）被前端当作模型失败，把服务端运行中的消息写成 error。
- 保存初始聊天失败后，草稿虽恢复，临时用户/助手消息仍留在上下文，重试发送重复消息。
- 404 过期续跑标识持续保留“继续处理”，用户反复请求同一无效任务。
- SSE 502/504 后已有正文或续跑 token 丢失，错误后被错误显示为 complete。
- 审批服务 503、429 或网络失败后，未确认操作被执行；失败后自动重试写操作。
- 401 的现有登录刷新机制失效，403 被误认为需要重新登录。

验证用浏览器接口夹具模拟版本推进及上述 HTTP/SSE 错误，检查没有旧快照写回或自动重试写操作；产物保存至 output/admin-ai-approval-panel-e2e/。
