## 部署与边界

1. 必须重新构建并部署后端和前端。旧格式会话失效，用户需要重新登录；这不是线上部署完成声明。
2. 学号末六位密码不再允许登录。受影响用户通过已绑定邮箱找回，或由教师核实身份后重置；导入结果中的随机密码只返回一次，应由授权人员通过可信渠道分发。
3. `GO_JUDGE_MAX_SUBMISSION_TIME_MS` 默认 120000，执行时限制为 1000–600000ms。长题库部署前应按真实测试点规模评估，超预算会产生 TLE，不应把安全预算误认为题目的单点时限。清理请求仍有独立的短超时。
4. 每个认证作用域的默认来源预算 120 次/分钟，邮件来源预算 20 次/分钟，全局预算 1200 次/分钟。可用 `AUTH_SOURCE_LIMIT_PER_MINUTE`、`AUTH_EMAIL_SOURCE_LIMIT_PER_MINUTE`、`AUTH_GLOBAL_LIMIT_PER_MINUTE` 调整。校园 NAT 应评估误伤；正确配置 `TRUSTED_PROXY_RANGES`，不要信任任意客户端转发头。
5. 按用户筛选队列是批次公平性改善，不是跨多个后端实例的严格全局每用户互斥；本次没有进行多实例压力或容量认证。
6. 延迟判题 HTTP 回归覆盖普通题路径。SPJ/通信题共用预算入口和现有回归检查，但未分别运行长耗时 E2E；管理员与教师所有批量改密入口也未逐一做 HTTP 穷举。邮箱绑定/改资料复用同一原子消费函数，未逐个动态复测。真实 SMTP 成功投递、生产 WAF 和实际线上镜像不在本次验收范围内。
