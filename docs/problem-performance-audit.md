# 大数据题目访问、保存与判题排查

验证日期：2026-10-25。修复在本地源码和构建中完成，未部署生产站点、未重启原有后端。

## 已确认原因与修复

1. 编辑页原先等待所有隐藏测试点下载后才显示题面。现在题面与隐藏数据分开加载；测试数据页只读取编号和字节数，点击单个测试点再读取正文、挂载文本框。
2. 原先“完成”和“保存测试数据”会上传所有正文，后端删除、重插全部测试点，再将全部正文返回。现在已有题目只提交显式增删改，未修改时浏览器不发写请求。新增 `/test-cases/summary`、`/test-cases/{caseId}` 和 POST `/test-cases/changes`；原完整接口保留兼容其他调用方。
3. 保存题面原先可能两次查询所有隐藏输入/输出，以检查是否能关闭特殊判题。现在只在从 SPJ/通信题切换为普通判题时检查，数据库执行存在性查询；保留 Java 空白语义，NBSP 不会误判为空输出。
4. 普通判题原先 `split` 大输出为大量 token 字符串。现在直接比较 token 在原字符串中的位置，避免为每个 token 分配字符串和数组；保留内部 ASCII 分隔和两端 Unicode 空白规则。
5. 新增权限校验覆盖元数据和单点内容；增量保存使用一个数据库事务，在写入前检查最终编号，支持编号互换，失败时回滚删除、临时编号与正文。

选手题目详情经真实 HTTP 验证没有传输隐藏测试数据。题目数据量不会通过这个详情 DTO 直接放大响应。

隔离 MySQL 数据库：8 个测试点，每点 2 MiB 输入、1 MiB 标准输出，总共 24 MiB。下表在同次运行中对比现有完整接口与新摘要接口，耗时包含本机 HTTP 传输与读取，不代表生产网络压测。

| 操作 | 响应字节数 | 本次耗时 |
| --- | ---: | ---: |
| 原完整测试点接口 | 25,166,656 | 238.27 ms |
| 新测试点摘要接口 | 736 | 20.1 ms |

题面保存三次：33.44, 13.09, 12.04 ms，隐藏测试点 ID 保持不变。
管理员和老师浏览器编辑单个测试点，仅提交该点约 1 MiB 的输入/输出，其他测试点不上传；打开题面和保存未修改的数据，均没有隐藏正文读写请求。

大输出提交受理耗时范围：15.27–29.55 ms。
测试使用真实 Spring 后端、数据库、队列和受控 HTTP 判题服务，验证 1 MiB 输出的 AC、末尾错误 WA、制表符等价和 Unicode 两端空白。**受控服务返回固定执行结果，没有测量真实沙箱程序的 CPU、磁盘和执行耗时；没有判题总耗时的生产前后对照。**
