# 课程重构失败场景（实现前确定，按最新多班级规则）

教师可以创建多个自己的课程；课程可关联多个该教师管理的班级；学生最多属于一个班级，自动加入本班关联的课程。未关联班级和其他教师不得使用该课程。所有关联班级共享课程题单。

- 多班级课程只让第一个班级的学生加入，其他关联班级未获得权限。
- 教师创建或编辑课程时混入其他教师的班级，导致跨教师授权；失败请求却留下部分关联。
- 教师查看、修改、归档、发布到其他教师的课程，或同 ID 的管理员与教师被混淆。
- 未关联班级的学生通过课程列表、详情、旧题单 URL、题解或伪造提交访问课程。
- 给已有题单的课程增加班级，新班无法看到已有题单；移除班级后旧授权/解锁缓存仍可用。
- 班级关联更新与发布题单并发，造成发布对象与课程班级不一致。
- 修改关联班级导致课程、题单、提交被复制或删除，影响历史数据。
- 重复班级 ID 导致重复课程、重复学生或统计人数翻倍；空班级的非草稿课程被发布。
- 课程统计和报表只统计一个班级，或漏掉零提交学生；未关联班级进入统计。
- 入班晚于课程创建没有自动加入；待审批学生获得权限；学生并发加入两个班级。
- 草稿课程、隐藏题目泄露；归档后仍可提交；密码解锁绕过班级成员校验。
- 题库或其他课程的 AC 被当成本课程作业；归档导致提交或判题明细删除。
- 单班历史课程迁移到关联表时漏掉班级、题单或提交；旧 API 单个 classId 不再可用。
- 页面仍写“只能一个班级”、不能多选、不能展示多班级；学生页面暴露其他班级学生名单。

验证以真实 Spring Boot、MySQL、Redis、go-judge、浏览器 E2E 为主。产出可重复脚本、report.json、迁移核对与截图；不新增单元测试。
