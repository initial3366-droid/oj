# 比赛提交 ZIP 批量取数：修改前失败场景

- 同一用户多次提交：CSV 与每条代码路径使用一致用户名，避免逐行/两轮查询。
- 多用户、缺失用户、空用户名：保留空字段及 data 路径兜底；不合并不同用户。
- 空比赛：仍产生两个带 BOM 的 CSV，不执行空 IN 用户查询。
- 题目快照不存在、contestProblemId 为空：保留原题 ID 回退标签；不修改题目映射语义。
- 中文、引号、逗号、换行用户名/显示名：保留 CSV 转义和路径清洗。
- 各语言扩展名、null 代码、非 ASCII 代码、代码长度缺失：原样保留字节和兜底长度。
- 提交排序：user_id、submit_time、id 排序及 ZIP entry 顺序不变；时间戳不同不应造成解压内容误报。
- 连续请求间更新用户名：立即反映，不引入跨请求缓存。
- 无登录、学生、非所有者内容管理员、缺失比赛：HTTP 状态与权限不变；拒绝请求不得读取代码数据。
- 成功导出仍记录 VIEW_CODE 安全审计日志；业务表校验和不变。
- 实测完整 HTTP SQL，区别榜单内部用户补查与导出新增批量读取；不把 Mapper 调用次数当作 SQL 次数。
- 使用独立临时数据库/Redis；最终停止进程并清理，保留 ZIP、逐项内容与 SQL 报告供复跑。
