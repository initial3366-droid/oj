# 后台学生操作密码复核：实现前失败场景

- 绕过浏览器直接调用批量/删除接口，在缺少或错误密码时仍能修改数据。
- 批量调整班级、移出班级、重置密码、重置 AI 额度、删除其中某个动作漏检。
- 单个删除或批量删除漏检；前台/教师权限能借操作密码提升为后台权限。
- 固定密码明文写入源码、前端构建、日志、URL、本地存储或测试文件。
- 密码哈希可直接作为请求密码重放；空值/超长值导致编码器异常。
- 可无限暴力尝试；Redis 不可用时验证放行。
- 密码错误后数据已变更；用户更换操作/取消后仍保存上一次输入。
- 重置学生新密码与操作验证密码混用；错误后丢失勾选名单。
- 删除提交重复触发；操作完成/取消后密码仍保留。

实现使用服务端 BCrypt（cost 12）固定加盐哈希；验证每次操作，不提供通用授权票据。
仅后台管理接口启用；教师班级管理继续使用其已有权限约束。
连续失败最多五次，窗口五分钟，按后台账号使用 Redis 原子限流，成功清除计数。
验证使用真实后端/MySQL/Redis + 浏览器 E2E；不新增单元测试。E2E 密码通过环境变量临时提供，不落盘。

## 已完成验证与部署

- 16 项真实后端 + 浏览器 E2E 通过；已有 177 项后端测试通过，前后端构建通过。
- E2E 覆盖所有批量动作拒绝错误/缺失密码、单个删除、全部重置 AI 额度拒绝未验证请求、哈希重放拒绝、共享限流及窗口恢复、取消清空输入、跨页选择保留、成功删除与数据清理。
- “全部重置 AI 额度”成功执行会影响全站，因此 E2E 只验证其拒绝请求和浏览器密码入口，未在共享本地数据库执行全站重置。
- 证据：`output/student-operation-password-e2e/report.json`、`cleanup.json`、`verification.json`、截图。
- 复现：临时设置 `QOJ_E2E_ADMIN_OPERATION_PASSWORD`，设置 `QOJ_E2E_BACKEND_JAR` 为新构建 JAR 路径后运行 `node tools/e2e/student-management.mjs`。
- 固定操作密码与管理员账号登录密码独立；调整固定密码需要替换服务端哈希并重新构建。
- 上线需要同步替换前端及后端 JAR 并重启后端。旧前端不会提交验证字段，会被新后端拒绝。操作密码传输应使用 HTTPS。
- 本地已构建，未部署服务器。
