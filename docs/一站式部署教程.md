# QOJ 一站式部署教程

面向刚拿到这个项目的新同学：从一台干净的电脑开始，到浏览器打开一个能注册、刷题、判题的完整 OJ，全程只需要 **装 Docker → 拿代码 → 跑一条命令** 三步。遇到问题直接翻文末的[常见问题](#八常见问题排查)。

部署完成后你会得到：

```
浏览器 → :80 前端页面（nginx）
            ├─ 题库 / 练习 / 比赛 / 排行榜 / 后台管理
            └─ 后端 API + 实时推送（同源反代，无需跨域配置）
                  ├─ MySQL 8.0（自动建表 + 种子数据）
                  ├─ Redis 7（缓存 / 会话）
                  └─ go-judge 判题沙箱（C / C++ / Java / Python）
```

除前端的 80 端口外，其余组件都只在 Docker 内部网络里互通，不对外暴露端口。

---

## 一、准备环境

### 硬件要求

| 项目 | 最低 | 推荐 |
|------|------|------|
| CPU | 2 核 | 4 核（判题并发才跑得动） |
| 内存 | 4 GB | 8 GB（判题沙箱默认限 2 GB，后端 2 GB，MySQL 1 GB） |
| 磁盘 | 20 GB | 40 GB SSD（镜像约 3 GB + 数据库与日志增长） |
| 系统 | Linux / macOS / Windows 10+ 均可 | — |

### 安装 Docker（含 Compose v2）

只需要 Docker，**不需要**手动装 Node、Java、Maven、MySQL——全部在镜像里构建和运行。

- **Linux**（Ubuntu/Debian 为例）：
  ```bash
  curl -fsSL https://get.docker.com | sudo sh
  sudo systemctl enable --now docker
  # 让当前用户免 sudo 使用 docker（装完重新登录生效）
  sudo usermod -aG docker $USER
  ```
- **macOS / Windows**：安装 [Docker Desktop](https://docs.docker.com/get-docker/)。
  - macOS：Docker Desktop → Settings → Resources，建议把内存调到 **6 GB 以上**。
  - Windows：需要 WSL2 后端（安装器会引导启用）；跑命令用 **Git Bash** 或 WSL 终端。

### 验证安装

```bash
docker version        # 能打印出 Server 版本即 daemon 正常
docker compose version # 需要 v2.x
```

> ⚠️ 两个注意点：
> 1. 判题沙箱 go-judge 需要**特权容器**，请使用默认的 rootful Docker（Rootless 模式不支持），并只部署在可信主机上。
> 2. 国内网络如果 `docker pull`/构建拉取镜像超时，先看[常见问题第 2 条](#2-构建时拉取镜像超时或极慢国内网络)配置镜像加速，再回来继续。

## 三、一键启动

### 方式 A：部署脚本（推荐）

```bash
./deploy.sh
```

这一条命令会依次完成：

1. 检查 Docker 是否就绪；
2. **首次运行**时自动生成 `.env.production`，里面已用 `openssl rand` 填好 5 个随机密钥（数据库密码 ×2、Redis 密码、JWT 密钥、判题令牌），文件权限 600 且已被 `.gitignore` 排除；
3. 构建前端、后端、判题沙箱三个镜像（**首次约 5–15 分钟**，之后增量构建走缓存，只需几十秒）；
4. 按依赖顺序启动全部服务：MySQL/Redis 健康检查通过 → 后端启动并自动执行数据库迁移（Flyway，88 个迁移建库+种子数据）→ 后端健康检查通过 → 前端启动；
5. 轮询就绪后打印访问地址。

看到类似下面的输出就是成功了：

```
[deploy] 服务已就绪
[deploy]   用户端:    http://localhost:80/
[deploy]   管理后台:  http://localhost:80/admin/
```

### 方式 B：纯 docker compose 命令（不想用脚本）

```bash
cp .env.production.example .env.production
# 编辑 .env.production，把 5 个 <64位随机串> 占位符换成随机值
# （openssl rand -hex 32 可生成一个；密钥必须 ≥32 位，否则后端拒绝启动）
docker compose --env-file .env.production up -d --build
```

脚本做的事和这三行完全等价，只是代劳了密钥生成和等待就绪。

### 方式 C：免源码部署（拉取预构建镜像，推荐生产使用）

项目每次发布版本都会自动构建多架构镜像并发布到 GitHub 镜像仓库（GHCR，可见文末"镜像发布机制"）。部署机**不需要源码**，只要 3 个小文件（`docker-compose.prebuilt.yml`、`.env.production.example`、`deploy.sh`，从仓库直接下载即可）：

```bash
mkdir qoj && cd qoj
# 下载/拷贝 docker-compose.prebuilt.yml、.env.production.example、deploy.sh 到此目录
./deploy.sh
```

`deploy.sh` 在没有源码的目录里会自动改用 `docker-compose.prebuilt.yml`（只拉镜像不构建，首次部署 1–3 分钟），密钥生成逻辑与方式 A 完全一致。

**国内直连加速**：GHCR 在国内直连可能偏慢，编辑 `.env.production` 加一行，镜像自动改走加速代理（无需登录任何账号）：

```
QOJ_IMAGE_PREFIX=ghcr.m.daocloud.io/initial3366-droid/oj
```

手动拉取也等价：`docker compose -f docker-compose.prebuilt.yml --env-file .env.production up -d`，原理与方式 B 相同，只是少了 `--build`。

> 📦 **镜像发布机制**（维护者视角）：推送 `v*` 标签到 GitHub 会自动触发 `.github/workflows/docker-publish.yml`，构建 `amd64 + arm64` 双架构镜像并发布为 `ghcr.io/initial3366-droid/oj-{frontend,backend,go-judge}`。**首次发布后**需在 GitHub 仓库 → Packages 页把这三个包的可见性改为 **Public**，否则别人拉取会得到 `denied`。

### Windows 用户

推荐在 **Git Bash** 里执行 `./deploy.sh`（Git Bash 自带 openssl）。不想用脚本的话，在 PowerShell 里走方式 B 手动编辑配置文件即可。

## 四、验证部署

```bash
./deploy.sh ps
```

5 个服务应全部显示 `healthy`：

```
SERVICE    STATUS
backend    Up 3 minutes (healthy)
frontend   Up 3 minutes (healthy)
go-judge   Up 4 minutes (healthy)
mysql      Up 4 minutes (healthy)
redis      Up 4 minutes (healthy)
```

然后打开浏览器：

| 入口 | 地址 | 说明 |
|------|------|------|
| 用户端 | http://localhost/ | 题库、练习、比赛、排行榜；右上角注册普通账号 |
| 管理后台 | http://localhost/admin/ | 见下方默认账号 |
| 部署机非本机时 | http://<服务器IP>/ | 云服务器记得在安全组/防火墙放行该端口 |

**登录管理后台**：

- 账号：`admin`
- 密码：`admin123`
- 登录时需要填写页面上的**图形验证码**（后台登录强制要求，属正常安全设计）

> 🔐 首次登录后台后请**立即修改默认密码**（后台 → 资料设置）。所有配置密钥都保存在部署机上的 `.env.production` 中，不要把这份文件发给任何人或提交到 Git。

想快速确认判题链路也正常：注册一个普通账号 → 后台随便开一道题 → 提交一段 `print("hello")` 的 Python 代码 → 等待返回 Accepted。

## 五、按需调整配置

所有配置集中在部署机上的 `.env.production`，改完重新执行 `./deploy.sh` 生效（只会重建受影响的部分）。

| 想做的事 | 改哪里 |
|----------|--------|
| 换访问端口（如 80 被占用） | `QOJ_HTTP_PORT=8080`，之后访问 `http://localhost:8080/` |
| 提高判题并发 | `GO_JUDGE_PARALLELISM=2`（**必须**同时加大 `GO_JUDGE_MEM_LIMIT` 和宿主机内存，每并发约 1–2 GB） |
| 小内存机器（如 4 GB 云主机） | `GO_JUDGE_MEM_LIMIT=1g`、`BACKEND_MEM_LIMIT=1g`、`GO_JUDGE_PARALLELISM=1` |
| 改 JWT 有效期 | `JWT_ACCESS_EXPIRE`（秒，默认 900）/ `JWT_REFRESH_EXPIRE`（默认 7 天） |
| 改管理后台路由前缀 | `VITE_ADMIN_PREFIX`（改的是前端路由，需要重建前端镜像） |
| 前后端分开部署 | 见文件内 `CORS_ALLOWED_ORIGINS` 注释；常规同源部署不需要动 |

## 六、日常运维

```bash
./deploy.sh                # 启动 / 升级（改代码或改配置后重新执行即可）
./deploy.sh ps             # 查看各服务状态与健康检查
./deploy.sh logs           # 跟踪全部日志（Ctrl+C 退出）
./deploy.sh logs backend   # 只看某个服务：frontend / backend / mysql / redis / go-judge
./deploy.sh restart backend# 重启单个服务
./deploy.sh down           # 停止全部服务（数据保留）
```

**数据都在哪**：MySQL 数据、Redis 数据、后端日志分别存在 Docker 命名卷 `qoj_qoj-mysql-data`、`qoj_qoj-redis-data`、`qoj_qoj-backend-logs` 中，`down` 不会删除它们。

**升级版本**：

```bash
git pull
./deploy.sh
```

数据库结构变更由后端启动时的 Flyway 自动完成，无需手工执行 SQL。

**备份数据库**（密码就是 `.env.production` 里的 `MYSQL_ROOT_PASSWORD`）：

```bash
docker compose --env-file .env.production exec mysql mysqldump -uroot -p qoj > qoj-backup-$(date +%F).sql
```

**恢复数据库**：

```bash
docker compose --env-file .env.production exec -T mysql \
  sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" qoj' < qoj-backup-2026-08-30.sql
```

**彻底重置**（⚠️ 连数据库、Redis 数据一起删掉，不可恢复）：

```bash
docker compose --env-file .env.production down -v
```

## 七、上线前安全清单

部署到公网服务器对外提供服务前，逐项确认：

1. ✅ 已登录后台并**修改默认密码** `admin123`；
2. ✅ `.env.production` 权限 600、不进 Git、不外泄（脚本已默认处理好，别手动破坏）；
3. ✅ MySQL/Redis 端口没有对外发布（默认编排就没有，别自己加 `ports`）；
4. ✅ 建议在前端容器外面再加一层 **HTTPS** 反向代理（宿主机 nginx/Caddy 或云负载均衡），转发时带上 `X-Forwarded-Proto`；
5. ✅ go-judge 是特权容器，只部署在可信主机，不要与其他不信任的业务混用；
6. ✅ 定期用上面的命令备份数据库。

## 八、常见问题排查

### 1. `./deploy.sh` 报 “port is already allocated” / 80 端口被占

宿主机 80 端口已有其他服务（常见于装过 nginx 的服务器）。编辑 `.env.production` 改成 `QOJ_HTTP_PORT=8080`，然后 `./deploy.sh`。

### 2. 构建时拉取镜像超时或极慢（国内网络）

报错特征：`DeadlineExceeded`、`failed to do request: dial tcp ... i/o timeout`，卡在 `load metadata for docker.io/library/...`。这是访问 Docker Hub 受阻，按下面任选其一：

**方法一：给 Docker 配置镜像加速（推荐）**

- Docker Desktop：Settings → Docker Engine，在 JSON 中加入后 Apply & Restart：
  ```json
  { "registry-mirrors": ["https://docker.m.daocloud.io"] }
  ```
- Linux：编辑 `/etc/docker/daemon.json` 加入同样内容，然后 `sudo systemctl restart docker`。

（镜像源地址随时间可能失效，可替换为其他可用的 registry mirror。）

**方法二：构建参数走国内源（npm/Maven 依赖慢时）**

编辑 `.env.production`，取消注释：

```
NPM_REGISTRY=https://registry.npmmirror.com
MAVEN_MIRROR_URL=https://repo.huaweicloud.com/repository/maven
```

### 3. 免源码部署拉取镜像报 `denied` / `not found`

- 该版本镜像还没发布：需要维护者推送 `v*` 标签触发发布流水线（见方式 C 的"镜像发布机制"）；
- GHCR 包可见性还是 Private：仓库 → Packages → 对应包 → Package settings → 改为 Public；
- `QOJ_IMAGE_PREFIX` 写错（注意末尾不带 `/`，格式为 `<仓库前缀>/oj`）。

### 4. 后端起不来，日志里有 “JWT_SECRET 使用了默认值” / “至少需要 32 字节”

你手动编辑 `.env.production` 时密钥没改到位，或者改回了示例值。重新生成：`openssl rand -hex 32`，替换 `JWT_SECRET` 和 `GO_JUDGE_AUTH_TOKEN`，再 `./deploy.sh`。

### 5. go-judge 容器反复重启 / 无法启动

- 使用了 Rootless Docker：判题沙箱需要特权容器，请改用标准（rootful）Docker；
- 内存不足：调小 `GO_JUDGE_MEM_LIMIT` 或降低 `GO_JUDGE_PARALLELISM`；
- 查看 `./deploy.sh logs go-judge` 定位具体报错。

### 6. Docker Desktop 下整体很慢 / 容器被 OOM 杀掉

给 Docker Desktop 分配更多内存（Settings → Resources → Memory，建议 ≥6 GB），或按第五节调小各服务上限。

### 7. 后台登录提示验证码错误 / 验证码不显示

验证码图片加载自同源 `/api`，先确认用户端页面能正常打开；再看服务器时间是否正确（默认编排已设置 `TZ=Asia/Shanghai`，自行改动过时区的话请改回）。

### 8. 判题一直 Pending

依次检查：`./deploy.sh ps` 里 go-judge 是否 healthy；`./deploy.sh logs backend` 是否有 go-judge 连接错误；提交语言的工具链在支持列表内（C / C++ / Java / Python，不支持其他语言）。

### 9. 想重来一遍干净的

```bash
docker compose --env-file .env.production down -v   # 删容器+数据卷
./deploy.sh                                         # 重新生成密钥并全新部署
```
