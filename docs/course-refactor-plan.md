# 班级课程重构：实施规则与使用说明

以用户最新要求为准：**教师可以创建多个自己的课程；每门课程可以关联多个该教师管理的班级；学生最多属于一个班级，可以自动加入本班关联的多门课程。** 未关联班级不能访问课程，其他教师不能管理或使用该课程。

## 课程与班级

```text
教师 A 的 C++ 程序设计课程
├── 关联：软件 2401 班、软件 2402 班（均由教师 A 管理）
├── 输入输出题单（两个班共享）
└── 循环题单（两个班共享）

教师 A 的算法基础课程
└── 关联：软件 2401 班

教师 B 的课程
└── 教师 A 不能管理或发布到该课程
```

课程名单直接由 `course_classes`、`class_members` 与学生主班级确定，无需重复维护选课名单。课程绑定班级后，现有学生与后续正式入班学生都自动加入；待审批申请不授予访问权。

课程可以增加或移除自己管理的班级，已有题单也同步授权。新增班级自动获得课程已有已发布题单；移除后立即失去课程、题单、题解和提交权限，密码解锁记录也不能绕过成员检查。课程、题单和历史提交不会因此复制、删除或改 ID。

## 页面与使用

学生主导航“我的课程”以及个人中心“班级课程”展示本班关联课程。课程详情包含题单、个人通过题数和完成状态。学生只看到自己班级的信息，不返回其他班级学生名单。

教师与管理员使用“课程管理”。创建和编辑时班级支持多选，教师选项仅包含自己管理的班级；后端逐项校验并在事务中保存，不能通过伪造请求加入他人的班级或修改他人的课程。管理员编辑教师课程时也不能把其他教师的班级加入其中。

进行中的课程至少关联一个班级，暂未选择班级时可保存草稿。课程题单从现有素材选用，或创建新素材后发布。题单访问范围自动覆盖课程全部关联班级；发布接口不能扩大到课程外班级或全体学生。

课程详情展示全部关联班级的学习情况，包含班级、学生、提交次数、通过题数、完成题单与未提交学生，并可按班级筛选。个人进度只统计本题单发布实例的提交，题库或其他课程的 AC 不混入本课程完成率。

课程归档停止新提交并保留内容。课程题单删除执行归档，保留原始提交与判题明细。已发布题单可在编辑页更换到同一教师的其他进行中课程；目标课程必须关联班级。变更同步班级权限、保留发布实例和历史提交，课程统计随归属更新。

## 题单开放时间

发布与编辑复用比赛的 Arco `DatePicker`（日期 + 时分），新发布默认当前时间开始、七天后截止，教师可以调整。截止时间必须晚于开始时间，时间按服务器及页面本地时间处理。

学生只在 `[startTime, endTime)` 内看到课程题单并查看、解锁、查看题解或提交；直接链接和密码缓存无法绕过截止限制。已打开的题单与题目页面会在截止时清除内容。教师管理与统计不受时间限制。编辑可调整开放时间，延长截止后可恢复学生访问。

`V103__practice_publication_schedule.sql` 为已发布实例增加可空时间字段；旧题单未设置时间时继续原访问规则，编辑页要求补充时间。

## 数据与兼容

- `courses`：名称、简介、学期、负责人账号类型和 ID、状态、时间。
- `course_classes`：课程与班级关联，`(course_id, class_id)` 联合唯一，可关联多个班级。
- `practice_publications`：保持原有发布实例、题目和提交关系，增加课程 ID、顺序、开始时间和截止时间。
- `practice_publication_classes`：与课程关联班级同步，保证现有管理接口返回的发布范围一致。
- `class_members.user_id`：唯一约束，继续限制学生最多一个班级，入班操作配合学生行锁。

课程状态为 `DRAFT` / `ACTIVE` / `ARCHIVED`。数据访问以关系表为准；旧 `courses.class_id` 仅作兼容摘要。

已有 `V101` 不修改；新增 `V102__course_multiple_classes.sql` 创建关系表，自动回填已有单班课程。课程、发布实例和提交 ID 保持不变。API 新增 `classIds` 和 `classes`，创建/更新使用班级 ID 数组，仍兼容旧请求的单个 `classId`。学生响应仅包含自己的班级，教师响应包含其课程的全部关联班级。

此前单班题单已按教师与班级归入历史课程。原公共和多班题单保留原数据与历史链接，未自动推断归属；历史题单也可通过编辑选择本人课程，已有提交和发布实例 ID 保留。

## 接口与路由

```text
GET /api/v1/courses
GET /api/v1/courses/{id}
GET /api/v1/courses/{id}/practices

GET/POST /api/admin/v1/courses
GET/PUT/DELETE /api/admin/v1/courses/{id}
GET /api/admin/v1/courses/{id}/practices
GET /api/admin/v1/courses/{id}/report
```

后台前缀沿用项目配置。现有发布接口 `/practices/{id}/publications` 新发布必须提供 `courseId`，并提供 `startTime`、`endTime`，目标班级由课程决定。课程关联变更和发布题单使用同一个课程行锁，避免并发产生不同访问范围。

学生页面为 `/courses`、`/courses/{id}`；教师为 `/teacher/courses`、`/teacher/courses/{id}`，管理员为其配置前缀下的相同路由。旧 `/practice` 跳转我的课程，旧题单详情链接保留并执行当前权限规则。

## 验证

失败场景在实现前列于 `docs/course-refactor-failure-cases.md`；不新增单元测试。运行前端构建和现有后端测试，主要业务使用真实 Spring Boot、MySQL、Redis、go-judge 与浏览器验证：

```sh
npm run build
cd backend && mvn test
node tools/e2e/course-refactor.mjs
```

E2E 需要本地 `.env`、MySQL/Redis/go-judge、Maven、Node 和 Playwright，使用一次性账号与业务夹具、独立后端 18082 和前端 5176，最后清理自身测试数据。产物位于 `output/course-refactor-e2e/`，包括 `report.json`、`migration-check.json` 和教师/学生页面截图。

新增多班级验证覆盖自动加入、未关联班级隔离、跨教师关联失败的原子性、增减班级对已有题单的即时授权、课程人数去重、跨班统计与筛选、多选创建，以及单班课程迁移兼容。保留实际判题、个人进度隔离、密码、退班及归档历史保留场景。

章节、课件、截止时间、多教师协作、独立手动选课不在当前功能范围。

题单时间与课程变更的新增失败场景见 `docs/practice-schedule-failure-cases.md`。E2E 当前覆盖 20 项场景，包括开放时间边界、编辑回显、更换课程保留成绩、并发迁移与班级修改，以及浏览器在截止时关闭内容。
